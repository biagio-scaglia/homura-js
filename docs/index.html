HomuraJS

High-performance time-travel debugging and state history management engine for JavaScript and TypeScript. A Directed Acyclic Graph (DAG) architecture conceived as "Git for application state".

Direct Answer / TL;DR

HomuraJS is a zero-dependency TypeScript library that records application state evolution as an immutable tree graph. It enables rewinding, fast-forwarding, creating parallel branch forks without destroying historical past/future timelines, deep semantic diffing, and inspecting states via native embedded DevTools.

Non-Destructive DAG Graph

Every state mutation diverges into a timeline branch without ever truncating previous historical branches.

Immutable Draft Proxy

Direct mutation syntax powered by zero-dependency Copy-On-Write proxies with structural sharing.

Deep Structural Diffing

Recursive diffing algorithm with precise dot-path tracking of added, removed, and modified properties.

Full Diagnostic DevTools

Visual graph timeline, collapsible JSON tree inspector, side-by-side diff viewer, and time scrubber.

Why HomuraJS?

In conventional state managers, history is maintained as a flat linear stack. When you travel back in time and perform a new update, all future states are irreversibly destroyed.

HomuraJS removes this limitation by modeling every state transition as a node in a Directed Acyclic Graph (DAG). Rewinding and applying a new change creates an alternative branch, preserving both past and future history forever.

Quickstart

Initialize a store and execute controlled time-travel mutations in seconds:

quickstart.ts 
import { createHomura } from '@homura-js/core';

// 1. Initialize instance
const homura = createHomura({
  initialState: { counter: 0, user: 'Homura' }
});

// 2. Mutate via Proxy Draft
homura.update(draft => {
  draft.counter += 10;
}, { label: 'Increment counter' });

// 3. Time travel
homura.undo(); // Counter rewinds to 0
homura.redo(); // Counter advances to 10

console.log(homura.getState()); // { counter: 10, user: 'Homura' }

State Management & Immutability

HomuraJS guarantees immutability via Copy-On-Write Proxy Drafts. Inside update(draft => ...), you write direct mutations: the engine applies changes only to modified paths while structurally sharing untouched state.

mutations.ts 
// Direct draft mutation
homura.update(draft => {
  draft.user = 'Akemi';
  draft.counter += 5;
}, { label: 'Update User' });

// Functional return mutation
homura.update(state => ({
  ...state,
  counter: state.counter + 1
}), { label: 'Functional Increment' });

// Direct full reset
homura.setState({ counter: 100, user: 'Homura' }, { label: 'Total Reset' });

Atomic Transactions & Batching

Combine multiple state updates into a single atomic history commit instead of cluttering your timeline with intermediate states:

transactions.ts 
// 1. Batch multiple mutations atomically
homura.transaction((draft) => {
  draft.name = "Biagio";
  draft.age = 21;
  draft.role = "developer";
}, { label: "Update Profile" });

// Result: Exactly 1 single history commit node created!
// Calling homura.undo() reverts all 3 fields in one single step.

Timeline Replay Engine & Bug Reports

Step-by-step automated time-travel replay engine for live debugging, QA testing, and exporting reproducible session bug reports:

replay-and-export.ts 
// 1. Replay timeline sequentially with speed multiplier
await homura.replay({
  from: "login-checkpoint",
  to: "checkout-entry",
  speed: 2, // 2x speed
  onStep: (entry, step, total) => {
    console.log(`[Replay] Step ${step}/${total}: ${entry.label}`);
  }
});

// 2. Export full reproducible state history report
const bugReport = homura.export();
// Save to "bug-report.homura" file for instant developer reproduction!

// 3. Developer imports bug report on another machine
homura.import(bugReport);
homura.jumpTo("crash-state");

DAG Graph & Branching ("Git for State")

Every state transition produces an immutable HistoryEntry<T> indexed in the DAG graph:

types.ts 
interface HistoryEntry<T> {
  id: string;
  parentId: string | null;
  childrenIds: string[];
  branchId: string;
  timestamp: number;
  label: string;
  state: T;
  metadata?: Record<string, unknown>;
}

If you travel back in history and dispatch a new update, HomuraJS automatically forks an alternative timeline branch without discarding prior history:

branching.ts 
// Rewind to a previous state
homura.jumpTo("past-node-id");

// This new update creates branch-2 without destroying previous history
homura.update(draft => {
  draft.user = 'Timeline Beta';
}, { label: 'Alternative Branch Point' });

// Get all timeline branches
const branches = homura.getBranches();

// Switch between parallel branches
homura.switchBranch(branches[0].id);

Branch Merging & Comparison ("Git for State")

Compare parallel branches to discover divergence points (Lowest Common Ancestor), diffs, and merge alternative feature timelines:

branch-merge.ts 
// 1. Compare two parallel branches
const comparison = homura.compare("main", "experimental-feature");
console.log(comparison.commonAncestorId); // Divergence point in graph
console.log(comparison.aheadCount);       // Commits ahead
console.log(comparison.diff);             // Deep recursive delta

// 2. Merge experimental branch into active branch
homura.merge("experimental-feature", {
  label: "Merge experimental feature into main"
});

Time Travel Navigation

Deterministic commands for traversing your application history:

Method Description
homura.undo() Rewinds to the parent node in the timeline graph.
homura.redo() Advances to the next child node in the active branch.
homura.rewind(N) Fast-rewinds backwards by N history steps.
homura.fastForward(N) Fast-forwards forward by N history steps.
homura.jumpTo(entryId) Jumps directly to any node ID in the DAG graph.

Snapshots & Milestones

// Instantly restore saved state

Structural Diff Engine

The pure-function diffing engine computes exact semantic delta changes between any two states:

diff.ts 
import { diffStates } from '@homura-js/core';

const stateA = { hero: { hp: 100, weapon: 'Sword' }, inventory: ['Potion'] };
const stateB = { hero: { hp: 75, weapon: 'Magic Sword' }, inventory: ['Potion', 'Shield'] };

const diff = diffStates(stateA, stateB);
console.log(diff);
// [
//   { path: ['hero', 'hp'], type: 'changed', oldValue: 100, newValue: 75 },
//   { path: ['hero', 'weapon'], type: 'changed', oldValue: 'Sword', newValue: 'Magic Sword' },
//   { path: ['inventory', 1], type: 'added', value: 'Shield' }
// ]

History Compaction & Enterprise Storage

Keep your memory footprint optimal with intelligent graph compaction and high-capacity storage backends like IndexedDB:

compaction-and-storage.ts 
import { createHomura, createIndexedDBAdapter } from '@biagioscaglia/homurajs';

// 1. Enterprise IndexedDB persistence for large browser applications
const homura = createHomura({
  initialState: { documents: [] },
  persistence: {
    adapter: createIndexedDBAdapter({ dbName: 'my_app_db', storeName: 'history_store' }),
    autoSave: true,
    debounceMs: 150
  }
});

// 2. Compact history graph down to 100 entries, preserving checkpoints
const prunedCount = homura.compact({
  maxEntries: 100,
  preserveSnapshots: true
});
console.log(`Pruned ${prunedCount} intermediate non-essential nodes`);

React 18+ Integration

The useHomura hook leverages native useSyncExternalStore APIs, ensuring zero tearing and fine-grained selector re-render optimizations:

Counter.tsx 
import { useHomura, HomuraDevTools } from '@homura-js/react';
import { homura } from './store';

export function Counter() {
  // Selector subscription
  const { state: count, update, undo, redo, canUndo, canRedo } = useHomura(
    homura,
    s => s.counter
  );

  return (
    <div>
      <h1>Count: {count}</h1>
      <button onClick={() => update(d => { d.counter++; }, { label: 'Increment' })}>+1</button>
      <button disabled={!canUndo} onClick={() => undo()}>Undo</button>
      <button disabled={!canRedo} onClick={() => redo()}>Redo</button>

      <HomuraDevTools homura={homura} position="floating" />
    </div>
  );
}

Frequently Asked Questions (FAQ)

What is HomuraJS?

HomuraJS is a JavaScript/TypeScript state management and time-travel debugging engine modeled as a Directed Acyclic Graph (DAG), conceived as "Git for application state".

How is HomuraJS different from standard Undo/Redo systems?

Standard Undo/Redo systems use a flat linear array stack that irrevocably destroys future states whenever a new mutation occurs in the past. HomuraJS forks non-destructive timeline branches, preserving all past and future states forever.

Which UI frameworks are supported?

HomuraJS core is framework-agnostic (@homura-js/core) and provides official packages for React 18+ (@homura-js/react), Vue 3 (@homura-js/vue), and Vanilla JavaScript (@homura-js/vanilla).

How to install HomuraJS?

Install the core package via npm install @homura-js/core or use the unified meta-package npm install @biagioscaglia/homurajs.

Complete API Reference

Method Parameters Return Description
getState() - T Returns the current immutable state tree.
update(updater, options?) (draft: T) => void, StateUpdateOptions HistoryEntry<T> Executes a Copy-On-Write draft mutation.
undo() - HistoryEntry<T> | null Rewinds to the parent node in the timeline graph.
redo() - HistoryEntry<T> | null Advances to the next child node in the active branch.
rewind(steps) number HistoryEntry<T> | null Fast-rewinds backwards by N history steps.
fastForward(steps) number HistoryEntry<T> | null Fast-forwards forward by N history steps.
jumpTo(entryId) string HistoryEntry<T> Jumps directly to any node ID in the DAG graph.
snapshot(name?, metadata?) string, Record<string, unknown> Snapshot<T> Creates a named immutable checkpoint of the state.
restore(snapshotId) string HistoryEntry<T> Restores the state stored in the snapshot checkpoint.
transaction(fn, options?) (draft: T) => void HistoryEntry<T> Batches multiple mutations into a single atomic history commit.
replay(options?) ReplayOptions<T> Promise<void> Replays timeline history step-by-step with configurable speed and hooks.
merge(branchId, options?) string, BranchMergeOptions HistoryEntry<T> Merges another branch timeline into the current active branch.
compare(branchA, branchB) string, string BranchComparison Compares two branches calculating common ancestor and structural diff.
compact(options?) CompactionOptions number Compacts history by pruning non-essential nodes to save RAM/disk.
diff(entryA, entryB?) HistoryEntry | T, HistoryEntry | T DiffChange[] Calculates the deep recursive structural delta diff.
